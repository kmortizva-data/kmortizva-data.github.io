  • Gradient descent is the engine of everything. Here it is computed by hand, and it converges by halving the remaining distance at every step.

Context

What this module solves

Module 2 trained models without looking inside. Here the engine is opened.

A line is fitted, what it means for a model to be wrong is defined, and that error is lowered step by step. That procedure, gradient descent, is the same one that trains a neural network of a billion parameters.

And the first knob that does move the result in this project appears: regularisation.

By hand

Before the theory: a toy example

Two batches. For each one we know how much the air was raised above normal, and how much extra silica came out.

BatchExtra airExtra SiO₂
112
224

We look for a single number, the slope, which we will call w. The prediction is w times the extra air. By eye you can see that w = 2 is right for both batches. We are going to get there without looking.

Step 1. Define what being wrong means

The error is the average of the squared misses.

error(w) = [ (w·1 − 2)² + (w·2 − 4)² ] / 2

Expanding, the two terms are multiples of the same thing:

error(w) = [ (w−2)² + 4·(w−2)² ] / 2 = 2.5 · (w−2)²

It is a parabola with its bottom at w = 2. Finding the best line means going down to that bottom.

Step 2. Start in a bad place

We start at w = 0, which is always predicting zero.

error(0) = 2.5 · (0−2)² = 2.5 · 4 = 10

Step 3. Know which way is downhill

The slope of the parabola at a point says which way it rises. For this parabola it is:

gradient(w) = 5 · (w − 2)
gradient(0) = 5 · (−2) = −10

Negative means the error drops if w increases. The descent rule subtracts the gradient multiplied by a small factor, the learning rate. With rate 0.1:

new w = 0 − 0.1 · (−10) = 1

Step 4. Repeat, and see the pattern

Every step cuts the remaining distance in half. The error is divided by four each time. It never reaches exactly 2, but it gets as close as needed.

Step 5. The learning rate decides whether it works

With rate 0.2 the first step lands right at the bottom:

new w = 0 − 0.2 · (−10) = 2      right first time

With rate 0.4 it overshoots and comes back to the start:

w = 0   -> 0 − 0.4·(−10) = 4
w = 4   -> 4 − 0.4·(+10) = 0
w = 0   -> 4 again ...

It bounces forever between 0 and 4 without ever getting closer. That is the learning rate: the size of the step. Too short and it takes an eternity. Too long and it does not converge.

Terms

Glossary

12 terms, in plain words
  • Linear regression. A model that adds up each variable multiplied by its own number. It predicts by drawing a line or a plane.
  • Coefficient. The number that multiplies a variable. It says how much the prediction changes if that variable rises by one unit.
  • Loss function. The formula that measures how wrong the model is. Here, the average of the squared misses.
  • Gradient. The slope of the loss function. It points to where the error grows.
  • Gradient descent. Repeating small steps in the direction opposite to the gradient, until the bottom is reached.
  • Learning rate. The size of the step. In Spanish, tasa de aprendizaje.
  • Convergence. The steps no longer changing the result appreciably.
  • Scaling. Putting every variable on the same scale before training.
  • Regularisation. A penalty added to the loss for having large coefficients. It forces the model to be simpler.
  • Ridge. Regularisation that shrinks all coefficients towards zero without zeroing any.
  • Lasso. Regularisation that does take coefficients to exactly zero, so it also selects variables.
  • Alpha. The regularisation knob. The higher it is, the more the coefficients shrink.
Method

Step by step

Step 1. Scale before anything else

Air flows hover around 300 Nm³/h and the pH around 9.5. Without scaling, the air dominates any comparison of coefficients just by being a bigger number.

Scaling subtracts the mean and divides by the standard deviation. Afterwards, a coefficient of 0.2 means the same thing wherever it comes from.

Step 2. Fit the line and read it

A linear regression on the 21 columns gives 21 coefficients. Each has a sign, and the sign is the first thing to audit against the chemistry.

Step 3. Check that the line is capable of little

A line only captures straight relationships. If the process has an intermediate optimum, the line misses it entirely.

Step 4. Penalise large coefficients

Regularisation adds to the loss a penalty proportional to the size of the coefficients. The model then has two goals at once. Be right, and do not exaggerate.

With noisy data and little signal, exaggerating is exactly what does harm.

Step 5. Choose the knob by looking at the curve

Alpha is not set by default. It is swept on a logarithmic scale and the result is drawn. The sweet spot is visible, and so is the collapse after it.

Result

The result, measured

What we expected. That the line would be worse than the tree, because the process is not linear. And that regularisation would change little, as usually happens with half a million rows.

What came out. The first, yes. The second, no.

ModelTest R²
Line without regularisation0.010
Tree, depth 3 (module 2)0.038
Regularised line, alpha 215,4430.061

Regularisation multiplies the R² by six, from 0.010 to 0.061. With that, the best linear model beats the three tree models of module 2.

What it means. That the signal is so weak that the unpenalised model spends itself fitting noise. By shrinking the coefficients almost to nothing, it generalises better.

The winning alpha is enormous, 215,443. In a problem with a clear signal, an alpha like that would crush the model. Here it is exactly what is needed, and that is the honest measurement of the project: there is very little to learn.

And the curve shows both drops. With alpha 100 it regularises nothing and stays at 0.0102. With alpha a hundred million it crushes everything and falls to 0.0012. The sweet spot has to be searched for, not assumed.

What this module leaves open

The alpha of 215,443 was chosen by looking at the result on the test set. That is cheating, even if it is a small and very common cheat.

The test set is touched once, at the end. If it is used to choose knobs, it stops being an honest measure. Module 4 fixes that with cross-validation, and along the way discovers that the result was more optimistic than it looked.

Traps

Watch out

  • The learning rate is not set by eye. With 0.2 the example lands in one step and with 0.4 it bounces forever. It is the most treacherous knob of gradient descent.
  • Scaling is mandatory if you are going to compare coefficients. Without scaling, the largest coefficient is usually the one of the variable with the smallest units.
  • The scaler is fitted with the training set only. Computing the mean with all the data lets information from the future in. It is leakage through preprocessing.
  • The signs of small coefficients are not reliable. Here two air columns come out with opposite signs. That is not chemistry, it is arbitrary sharing between similar variables.
  • An enormous alpha is not a mistake. It is the data saying there is little signal. It is reported, not hidden.
  • Choosing the knob by looking at the test set is cheating. Module 4 corrects it, and the number goes down.
Analogy

Metallurgical bridge

Gradient descent is searching for the optimum of an operating variable without knowing the curve. An operator looking for the frother dose that maximises recovery does not have the curve drawn. He raises the dose a little, sees whether recovery improves, and decides the next move with that information.

The learning rate is the size of the adjustment. Moving the dose by 1 gram per tonne takes a whole shift to get there. Moving it by 200 overshoots, the froth runs out of control, and the operator over-corrects the other way. The process oscillates and never settles. It is exactly the bounce between 0 and 4 in the example.

Regularisation is not trusting a single test. If a laboratory test suggests a large change of reagents, the experienced metallurgist does not apply it whole. He applies part of it and waits for confirmation. Shrinking the coefficient is that same prudence, written as a formula.

Review

Review

What is gradient descent, in one sentence you could say in an interview?

It is walking down a slope blindfolded, feeling the gradient under your feet and taking a step downhill, over and over.

The slope is the loss function, which measures how wrong the model is. The gradient is the slope at the point where you are. You subtract the gradient multiplied by the learning rate, and that gives the next point.

In this module's example you start at zero with rate 0.1. Every step cuts the distance in half: 0, then 1, then 1.5, then 1.75. It is the same procedure that trains a neural network with billions of parameters.

With rate 0.4 the example bounces between 0 and 4 forever. Why?

Because the step is longer than the distance to the bottom, and it lands on the other side at the same height.

At w = 0 the gradient is −10, so the step is 0.4 times 10, that is, 4. It jumps to w = 4. There the gradient is +10, the step is 4 again, and it goes back to 0. The error is identical at both points, so it never improves. It is the same as an operator who over-corrects every shift: the process oscillates and does not converge.

Regularisation lifts the R² from 0.010 to 0.061. What does that say about the data?

It says there is very little signal. Regularisation only helps when the unpenalised model is busy fitting noise.

The winning alpha is 215,443, an enormous value. An alpha like that shrinks the coefficients almost to zero. The model improves sixfold by going almost mute, so almost everything before was noise. The reading is not "regularisation works very well". It is "these data have very little to tell".

Two air columns come out with opposite signs. Can chemistry explain it?

No, and claiming so would be making things up. The two coefficients are −0.246 and +0.202, which are small values on scaled variables.

When several variables are correlated with each other and the signal is weak, the regression shares the weight among them almost arbitrarily. A small change in the data can flip the signs. The correct reading is that the block of air columns matters, without assigning a direction to each column separately. The forest's importance confirms it, since it does point at air consistently.

Alpha was chosen by looking at the test set. What is the problem with that?

That the test set stops being an honest measure as soon as it is used to decide anything.

Trying 28 values of alpha and keeping the one that scores best on test turns the test into part of the training. The reported 0.061 is then optimistic, because it incorporates a decision taken with that same information. The right thing is to choose the knob with cross-validation inside the training set, and touch the test once at the end. Module 4 does that, and the resulting number is quite a bit worse.
