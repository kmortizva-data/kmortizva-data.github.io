TikTok

Three hundred trees and nine variables tie with a single question on a single column. The credit belonged to the data.

19,084 videos50.3% claimsaccuracy 0.9958contribution of the model +0.0000
Brief

The brief

TikTok wants to reduce the queue of claims waiting for human review. The goal was announced in Course 2 and it is this: classifying automatically whether a video contains a claim or an opinion.

This is that model. And half of the project is not about building it, it is about finding out who did the work.

Question

The question

Can it be decided automatically whether a video is a claim? And if it comes out well, did the model do it or was it already done?
Data

The data

tiktok_dataset_raw.csv, 19,382 videos. The same 298 incomplete rows Course 2 found are removed for the same reason, so 19,084 remain.

And a difference from Course 4 worth looking at. That project predicted whether the account was verified, with a split of 93.6% against 6.4%, so it had to undersample and could not trust accuracy. Here the target sits at 50.3% against 49.7% and nothing has to be balanced.

Same data, opposite problem: the imbalance is not a property of the file, it is a property of the question you ask it.

Control

The control, fixed before looking at anything

Course 2 had already measured that a claim is viewed 101 times more than an opinion, with the two distributions almost not overlapping. With that signal, any model is going to come out almost perfect, so a result above 99% will not be a success: it will be a confirmation.

That is why, before training anything, a deliberately ridiculous comparison model was fixed: a tree with a single question on a single column, the views. The whole rule it learned fits in one line:

If the video goes past 10,031 views, it is a claim.

With that alone it gets 99.61% right in validation.

Deciding afterwards what counts as a good baseline is how a project convinces itself of being impressive. It gets decided before.

Exploration

What the exploration showed

The most-viewed opinion in the whole file9,998 views
The cut the model chose10,031 views
The least-viewed claim1,049 views

The two classes are separated by a line, and that is why any algorithm finds it. No machine learning was needed: sorting a column was needed.

Model

The model, and why this model

Three-way split, 60/20/20 stratified, with the test set set aside from the start: 11,450 for training, 3,817 for validation and 3,817 for test.

Four families measured in validation, and then grid search with four-fold cross-validation for the two tree ones: 24 combinations in 38 seconds for the forest and 12 in 6 for the boosting. The champion, chosen in validation, was the tuned forest with 0.9979 of AUC.

Comparison

The comparison

On the test set, looked at a single time, with the control inside the table:

ModelVariablesAccuracyAUC
One question, one column10.99580.9958
Logistic regression90.99400.9973
Tuned boosting90.99480.9979
Tuned forest, 300 trees90.99580.9986

Nine variables and three hundred trees contribute exactly 0.0000 of accuracy over a single question. The logistic regression, with all nine, gets less.

The AUC does improve, from 0.9958 to 0.9986, and that is real: the forest ranks the doubtful cases better. But when it comes to deciding, which is what gets deployed, it improves nothing.

The importance says it from another place: the five interaction counters are the whole model, and whether the account is verified contributes exactly zero. And those five counters correlate with each other above 0.55, as measured in Course 4, so they are not five signals: they are one shared out.

Result

The result, translated

Here is the uncomfortable part, and it goes before the number.

A gap like that does not exist on a real platform. No opinion video on TikTok has a ceiling of ten thousand views. It appears when someone generates two populations by drawing them from different ranges, and this data is synthetic, created by TikTok for the certificate.

A model with 99.58% on this file has measured how the file was generated, not how the platform behaves.

Course 2 already declared the data as synthetic in its limitations. This is what that limitation costs when you try to build on top of it.

And the only videos with something to learn are 65 of 11,450, all of the same kind: claims almost nobody watched, below the cut. The distance between 0.9958 and 0.9986 of AUC is played out entirely in there, and none of the four models resolves them.

Decision

What gets decided with this

  1. Do not deploy this as a content classifier. What it learned is a views threshold that only exists in the practice file.
  2. Use the one-question rule as a mandatory baseline in any future work on this data. If a new model does not beat it, it has contributed nothing.
  3. Keep what it does teach: how to compare against a control, how to tune with cross-validation and how to read variable importance.
  4. If this were a real brief, ask for real data before anything else.
Limits

Limitations

  • The data is synthetic. It is the main limitation and it contaminates the business conclusion, not the methods.
  • The five counters are correlated with each other above 0.55. They are not five independent signals.
  • The test set was looked at once, after choosing the champion in validation.
  • The control is a one-question tree, that is the simplest possible thing. That a model does not beat that does not mean no model can: it means that **with this data there is no room** above 99.6%.
